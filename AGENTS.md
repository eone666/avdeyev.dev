# Rust TUI workflow

This worktree intentionally uses Rust only: Ratatui for the common UI,
Crossterm for native terminals, Ratzilla/WebAssembly for browsers, and tiny_http
for the server. Do not introduce Bun, Node, Vite, a frontend framework, or a
separate HTML implementation of the portfolio into the website. The explicitly
authorized exception is the isolated `cv/` Bun/Forme PDF generator and its
independent GitHub Actions job. Do not remove this generator or its PDF/JSON checks.

Build reusable widgets in `tui/src/widgets.rs` before composing them into
`App::render`. Widgets own layout, spacing, colors, and interaction visuals.
Keep browser/native host code responsible only for platform input and APIs.
The HTML template in `web/index.html` is a loader and accessibility shell; WASM
owns the interface. `cargo xtask metadata` generates `public/index.html` with
Schema.org JSON-LD from the same content data. Keep terminal launch instructions
in `shared/launch.rs`, used by both the WASM header and HTML generation.

`tui/content.json` is the single source for portfolio content. CV data lives in
`cv/resume.json`; `public/cv.pdf` and `public/resume.json` are generated by `bun run --cwd cv build`.

Preserve first-key focus reveal, J/K and arrows, immediate H/L tab changes,
Enter, C, ?, Escape, pointer/keyboard transitions, Shift/text selection, touch,
and native browser link behavior. Native terminals additionally support Q and
Ctrl-C to exit, wheel scrolling, and OSC 52 clipboard copy.

Render on changes only. Do not add a permanent browser animation/render loop.
Check 320, 390, 680, 768, and desktop widths, every tab, short terminal windows,
mouse, touch, keyboard, and focus transitions. Provide a working local URL.

Run `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`,
and WASM checks/builds after relevant changes. Do not edit the parent checkout.

Production deployment is `.github/workflows/deploy.yml`: push to master,
checked builds, complete GitHub Release, then Cloudflare Worker deployment.
Keep native binaries in public GitHub Releases. Deploy JS/WASM with Cloudflare
Static Assets, using commit-versioned paths. Smoke-test the final optimized WASM
locally in a browser before pushing. Binaryen 108 corrupts the externref table; use 116.
`public/install.sh` is the literal production installer; never template it or
add local-download fallbacks. `public/install-dev.sh` is dev-only.
